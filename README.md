# Контур — мини-CRM «Объекты и задачи»

React + TypeScript + Vite + Supabase. Постановщик управляет объектами и задачами, исполнитель видит назначенные ему задачи и переводит их через разрешенные статусы.

Рабочее приложение: https://stroy-crm-seven.vercel.app. Объяснение для руководителя: [`docs/for-manager.md`](docs/for-manager.md).

## Локальный запуск

```bash
pnpm install
cp .env.example .env.local
pnpm dev
```

Заполните `.env.local` URL проекта и **publishable** ключом из Supabase. Секретный ключ и `service_role` во фронтенд не передаются. Без переменных окружения запускается локальный UI-прототип с данными в `localStorage` и переключателем ролей; он нужен только для просмотра интерфейса.

## База и тестовые данные

Миграции в [`supabase/migrations`](supabase/migrations) создают таблицы, RLS, ограничения на изменяемые столбцы и атомарную функцию `transition_task` для смены статуса с записью истории. Вспомогательная проверка роли находится в закрытой схеме. Профили создаются администратором после создания пользователей Supabase Auth. Открытая регистрация отключена в `supabase/config.toml` и в проекте Supabase.

Тестовый набор: один постановщик, два исполнителя, три объекта и не менее шести задач в разных статусах. Пароли генерируются скриптом `scripts/provision-demo-users.mjs` и сохраняются только в локальном `.env.demo` (файл игнорируется Git). После создания пользователей выполняется `supabase/seed.sql`.

Проверка прав прямыми API-запросами:

```bash
node scripts/check-security.mjs
node scripts/check-ui.mjs
```

Скрипт проверяет видимость задач и объектов, запрет прямого изменения статуса и истории, повышение роли и недопустимые переходы.

## Структура фронтенда

- `src/App.tsx` собирает экран и обрабатывает состояния входа и загрузки.
- `src/features/workspace/useWorkspaceData.ts` загружает сессию и данные; `useCrm.ts` хранит состояние интерфейса и вычисляет видимые списки.
- `src/features/workspace/workspaceActions.ts` содержит операции над объектами и задачами. Правила переходов и доступы по-прежнему проверяются в Supabase.
- `src/features/auth`, `objects`, `tasks` и `workspace` содержат компоненты соответствующих экранов; `src/styles` разделяет базовые стили, контент, окна и адаптивность.

Форматирование: `pnpm format`; проверка: `pnpm format:check`.

## Принятые решения

- Любой постановщик может принять или вернуть на доработку задачу на проверке.
- Постановщик может редактировать поля задачи, включая исполнителя, в любом статусе, но статус меняется только через разрешенный переход.
- После переназначения прежний исполнитель сразу теряет доступ к задаче.
- Удаление объекта удаляет его задачи и их историю; удаление задачи удаляет ее историю. Для реального продукта вместо этого стоит согласовать архивирование.
- Исполнитель может читать имена и роли других участников, чтобы видеть автора и исполнителя в карточке своей задачи, но не может читать чужие задачи.

## Безопасность

RLS работает для всех таблиц. Прямые записи в `profiles` и `task_status_history` запрещены клиентской роли. Прямой `UPDATE` статуса задачи запрещен правами на столбцы. Функция `transition_task` блокирует строку задачи, проверяет роль, назначение, текущий статус и комментарий для доработки, затем меняет статус и добавляет историю в одной транзакции.
